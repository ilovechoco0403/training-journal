# 訓練日誌 v1.1.0

後續修改與驗證狀態請見 [版本修改紀錄](CHANGELOG.md)。每次更新專案檔案都須同步記錄，工作規則見 [AGENTS.md](AGENTS.md)。

深色、手機優先的個人訓練日誌。網站程式放 GitHub Pages；你填寫的訓練與身體資料只保存在目前裝置的瀏覽器，不會傳到 GitHub。不需要登入、不需要 iCloud。

## 放到 GitHub Pages

建議建立獨立 repository，避免覆蓋原本的 daily-checkin。

1. 在電腦解壓縮下載的 ZIP。
2. 登入 GitHub，新增 repository，名稱可用 `training-journal`。若使用免費 GitHub Pages，一般使用 Public repository；公開的是網站程式，不含你在手機填寫的紀錄。
3. 在 repository 選 **Add file → Upload files**。把解壓後資料夾「裡面的內容」全部拖進去，保留 `vendor` 資料夾；確認 `index.html` 在 repository 最上層，而不是多包一層資料夾。
4. 選 **Commit changes**。
5. 到 **Settings → Pages → Build and deployment**，選 **Deploy from a branch**。
6. Branch 選 **main**，資料夾選 **/(root)**，儲存。
7. 等待 GitHub 顯示網站網址。若 repository 使用 `training-journal`，預期網址為 `https://ilovechoco0403.github.io/training-journal/`；此網址需你完成上傳與啟用後才存在。
8. 手機開啟網址，iPhone 使用 Safari 的 **分享 → 加入主畫面**；Android 使用 Chrome 選單的 **安裝應用程式／加到主畫面**。

網站不需要建置或安裝套件，整包檔案可直接上傳。無法單獨只上傳 index.html，因為樣式、程式與 Excel 元件放在其他檔案。

## 第一次使用

1. 課表安排 → 點下週某一天的「＋」→ 選跑步、重訓 A／B／C 或其他模板。
2. 跑步只要填一行課表名稱，例如 `40′FR`；可加分類或自訂標籤。
3. 重訓會帶入已設定的動作、組數、目標次數；可以調整當天內容。
4. 訓練後，在總覽或日期卡片點「記錄成果」。
5. 回顧頁可依日期、類型、狀態、標籤與文字搜尋。預設顯示完成與部分完成，選「所有狀態」也能看到未執行或未來課表。
6. 右上角設定可管理模板、目標賽事、備份與還原。

同一天可以有多個訓練。每日身體狀態只填一次，可在總覽編輯，舊日期可在課表安排的月曆選擇日期，點「身體狀態」填寫；休息日也能記錄。

## 記錄方式

- 每日：自覺狀況 1–5、睡眠分數 0–100、痠痛 0–10、HRV ms、痠痛部位；可留空。
- 跑步：距離 km、時間、配速、心率 bpm、RPE 1–10、氣溫 °C、濕度 %、心得。
- 時間可填 `40:00`（40 分）或 `01:20:00`。配速填 `5:25`。輸入距離和時間時會自動計算配速，也可手動修改。
- 重訓：每組重量與次數／秒數，單側動作可左右拆開。啞鈴記單顆重量；槓鈴記含槓總重；徒手重量可空白。
- 深蹲／腿推等動作會出現選單，選擇當天實際做的項目。
- 核心不預填組數，可在模板或當次課表設定動作、組數與秒數。
- 部分完成與未執行必須填原因。其餘成果數據可空白。
- 原定課表與成果分開保存，臨時新增或略過動作不會改掉原定內容。
- 手動修改已有課表時，前一版原定內容會保存在完整備份的資料中。第一版介面不提供版本回復；如需維持原始計畫，請只在成果頁記錄調整。

## 跑步逐組紀錄（v1.1.0）

安排課表時可選「間歇」、「變速跑」或「法克雷特」。尚未填過成果的間歇與變速跑，預設使用逐組紀錄；法克雷特與其他分類維持整次紀錄。已有成果的舊紀錄仍保留整次模式，可在成果頁手動切換。

每組可填跑段距離（公尺）、時間與配速，以及恢復距離（公尺）與時間，全部選填；空白不當成零。時間使用 `分:秒` 或 `時:分:秒`，例如 200m 跑休兩分鐘填「200」與「2:00」。跑段距離與時間會自動計算配速，也可再手動覆寫。原地休息只填恢復時間即可。

可新增、複製上一組或移除組別，最多 200 組。切回整次模式會保留逐組資料；要刪除組別請切回逐組後移除。整次總距離仍獨立填寫，包含暖身及收操，週跑量不會重複加總組別。

Excel 增加「跑步逐組」閱讀工作表；完整還原仍使用「備份資料」。請以新版匯入包含逐組資料的備份；可繼續匯入舊版備份。

開發驗證可執行 `node test-running-laps.cjs`。本機瀏覽器驗證留下名稱以「測試：」開頭的示範課表，與手機及 GitHub Pages 資料分開。

## 模板與標籤設定

可新增、刪除、改名模板，設定預設動作、顯示哪些成果欄位，以及自訂欄位。

自訂欄位支援文字、多行文字、數字、選單，可放在安排、成果或兩者。單行文字或選單可勾選「加入標籤」。模板名稱、跑步分類與手動標籤會自動成為篩選條件。動作標籤可在重訓模板開啟。

修改模板只影響之後新增的課表，不會回寫過去紀錄。

## 備份與還原

設定 → 匯出 Excel，將 `.xlsx` 保存到手機檔案，也可手動傳到電腦。請確認下載完成。沒有雲端同步，另一個裝置不會自動出現資料。

Excel 包含：使用說明、訓練紀錄、每組成果、每日身體狀態、模板、自訂欄位、目標賽事、備份資料。完整備份也含未來課表與設定。

**還原使用「備份資料」工作表。請勿修改或刪除它。** 其他工作表便於閱讀與分析；修改這些閱讀表格不會改變匯入結果。要修改訓練內容，請在 App 內編輯。

匯入前會顯示數量及重複課表數，可以選：

- 合併並保留本機重複版本。
- 合併並以備份重複版本取代。
- 完整還原：用備份取代目前所有資料。

課表／模板／賽事依 ID 判斷重複；每日身體狀態依日期判斷。不同 ID 的同一天訓練會各自保留。不要連續匯入其他地方重新建立、但內容相同的訓練，因為它們會有不同 ID。

開始累積至少 3 筆課表但尚未備份，或距離上次匯出超過 14 天，總覽會提醒。清除瀏覽器資料、移除網站資料或裝置故障都可能造成遺失。偶爾另存一份到電腦。

## 離線與更新

第一次連網開啟並完成檔案下載後，會快取必要檔案。之後同一個網址／主畫面 App 可離線記錄；Excel 元件也已包含在檔案中，離線可匯出與還原。首次離線使用前，建議先開飛航模式試一次。

網站更新前先備份。開發者更新檔案時須一併修改 `sw.js` 的 CACHE 版本名稱；使用者連線開啟後，關閉這個網站的所有分頁與主畫面 App，再重新開啟，讓新版本生效。

使用固定網址與入口。瀏覽器與主畫面 App 的儲存區可能因系統而不同，換入口時先備份，必要時匯入。不要用瀏覽器私密模式長期記錄。

## 驗證與限制

已驗證每日記錄、跑步成果與配速計算、重訓逐組與左右拆分、模板快照、自訂標籤、搜尋篩選、賽事、儲存後重新載入，以及真實 XLSX 二進位匯出／還原與資料校驗。

本次未能進行真實 iPhone／Android 瀏覽器畫面與離線安裝測試。上傳後請先用一筆測試紀錄確認填寫、下載、還原及飛航模式操作，再開始長期使用。

## 更新發布注意事項

## 身體狀態與強度篩選（v1.1.0）

回顧 → 訓練資料庫 → 展開「身體狀態／強度篩選」，可針對自覺身體狀況、睡眠分數、痠痛、HRV 及單次 RPE 選擇小於、等於、大於等比較條件。選好比較方式並輸入門檻後才生效，也可單獨搜尋「未填寫」。空白不當成 0，多項條件須全部符合，並與日期、標籤、類型及文字搜尋一起使用。

例如執行狀態選「未完整完成（部分完成＋未執行）」，睡眠分數選「小於」、門檻填 70。尚待執行的課表不包含在此狀態中。

每日身體數據按訓練日期自動連結，不複製到各項成果；同一天只需填一次。卡片只補充這次篩選使用的數據。RPE 取自各次成果，目前沒有填 RPE 的紀錄屬於未填寫。收合篩選區仍保留條件；「清除篩選」會一併重設。篩選只影響下方訓練清單，上方本週／本月執行概覽仍按其原有期間統計；此版本尚未提供疲勞與完成率的分組比較。

可執行 `node test-recovery-filters.cjs` 驗證篩選規則。資料格式與 Excel 完整還原方式不變。

## 發布與取得新版

每次更新請將整組網站檔案一次提交到 GitHub，不要分批提交樣式與離線快取。v1.1.0 在入口的 CSS／JavaScript 網址加入版本號，離線安裝時重新向網路取得資源；後續修改時須同步調整入口網址、快取清單與快取版本。

部署完成後，手機保持連網開啟網站並等候下載，再關閉所有網站分頁及主畫面 App 後重新開啟；Safari 與主畫面入口需各自完成更新。設定頁顯示 1.1.0 可確認新版程式已載入。更新不需要清除網站資料，也不會變更訓練資料鍵或 Excel 備份格式。
